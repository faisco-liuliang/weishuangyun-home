# 维双云品牌 GEO 诊断

测试日期：2026-10-21（Asia/Shanghai）  
对象：维双云独立品牌站 `https://wsy.fkw.com`  
依据：`fanke-brand-geo-audit` 技能及其品牌 GEO 操作手册

## 结论

维双云官网已经具备较完整的第一方实体信号：品牌名在标题、首段、产品卡、FAQ、页脚和 JSON-LD 中基本统一；产品线也能对应到商城、官网、教育、轻应用和门店系统。线上首页可访问，`robots.txt` 和 `sitemap.xml` 均可抓取，首页 canonical 指向 `https://wsy.fkw.com`。

当前 GEO 风险主要来自实体关系和事实可信度：

1. 公开搜索中，`litingyun.fkw.com` 出现多篇“维双云是什么”文章，形成跨品牌承接和归属混淆。
2. 维双云站内文章把“维双云”和“立亭云”作为同一选型名单中的不同对象，首页博客摘要也出现“立亭云”字样，容易让模型建立错误的品牌关系。
3. “5 万+企业”“400+模板”“198 元/年起”“99 元/年”等数字和案例结果在官网、博客和第三方页面反复出现，但当前页面没有给出可回查的证据页、统计口径或更新时间。
4. 仓库源代码与线上页面存在内容漂移：仓库 FAQ 仍有“99 元/年”，线上首页主叙述为“198 元/年起”；首页线上内容比仓库当前代码更丰富，说明需要建立发布版本和事实台账。
5. `Organization.sameAs` 为空，JSON-LD 没有公司主体、备案、官方账号或可信外部资料链接；这削弱了实体消歧能力。

按技能的稳定性分级，目前只能判为 **S1/S2 之间**：官网自身的品牌信号已形成，但没有本次对话中可复核的豆包、元宝、通义、文心、Kimi 等 AI 独立对话原始回答，因此不能声称已达到 S3 或 S4。

## 官网和技术信号审计

### 已具备

- 首页 title、description、canonical 和 `metadataBase` 指向维双云官方域名。
- 首页首屏、关于页、产品页、FAQ、页脚反复使用“维双云”作为主语。
- `Organization`、`WebSite`、`ItemList` JSON-LD 已存在，产品 URL 可回查。
- FAQ 结构化数据与首页可见问答相对应。
- `robots.txt` 允许抓取首页和产品页，明确提供 `sitemap.xml`。
- sitemap 已覆盖首页、产品中心、产品页、价格、案例、关于、博客及文章。

### 高优先级问题

1. **跨品牌文章归属混淆**：搜索结果中 `litingyun.fkw.com/blog` 出现“维双云是什么”类文章；站内 `lib/blog-data.ts` 也多处将“维双云”和“立亭云”放进同一比较/组合叙述。应建立品牌关系页或删改不具备证据的跨品牌归属表达。
2. **外部证据不足**：`sameAs: []`，没有可核验的公司、备案、商标、官方账号或正式媒体链接。应只加入真实存在且管理员确认的公开 URL。
3. **数字承诺缺来源**：关于页和案例页使用“5 万+企业”、案例增长率、会员数、GMV 等数字；博客使用“400+模板”“0 抽佣”等表述。每个数字需要统计口径、时间点、证据 URL 或改为“页面所列参考”。
4. **价格口径冲突**：线上首页当前显示 198 元/年起，仓库 FAQ 仍有 99 元/年；“买二送二折算”必须在同一页面解释原价、付款年限、活动有效期和不包含项。
5. **页面承接缺口**：页脚指向 `/docs`、`/privacy`、`/terms`，但应逐一确认公开页面真实存在、标题和品牌归属正确，否则会形成死链或空页面信号。
6. **结构化数据可进一步细化**：产品页应为每条产品线使用真实可见的 `Product`/`Service` 信息、适用场景和价格边界；不要把未经证明的评分、排名、用户量写入 JSON-LD。

## 建议的整改顺序

1. 先处理跨品牌实体关系：盘点 `lib/blog-data.ts` 中所有“立亭云/凡科/乔拓云”等名称，逐篇确认是否为有证据的比较对象；没有证据的组合、母子或同属表述改成中性选型说明，或移到独立的品牌关系页。
2. 在 `/about` 建立一段可核验的公开身份句：品牌名称、运营主体、官网、服务范围、更新时间；没有正式主体资料时不要补写公司归属。
3. 统一价格口径：首页、FAQ、关于页、价格页、博客、JSON-LD 使用同一基准价，并明确“活动折算价”和适用条件。
4. 对“5 万+、400+、案例增长率、0 抽佣、响应时间”等事实建立内部证据台账；无法提供来源的内容改为范围、示例或条件化表述。
5. 给产品页补 5 至 8 个带答案的 FAQ，重点回答旧入口关系、版本范围、支付/退款、数据导出、源码/私有化、第三方成本和上线验收。
6. 确认 `/docs`、`/privacy`、`/terms`、`/sitemap.xml` 等链接均返回正确页面，并检查品牌名、标题和 canonical。
7. 整改后用同一问题集在至少 3 个 AI 平台各跑 3 轮，保存完整回答、日期、联网状态、引用 URL、品牌名和标签；只有达到 2/3 轮正确出现，才记为初步稳定。
